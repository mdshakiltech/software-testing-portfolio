# ShoppersStack – Test Plan

## 1. Project Overview
ShoppersStack is an e-commerce web application. This project focuses on practising manual software testing of the application's available features and user workflows.

## 2. Testing Objectives
- Verify that available features work as expected.
- Identify defects and unexpected behaviour.
- Validate input fields, error messages, and user workflows.
- Record test results and report defects.

## 3. Scope of Testing
The following modules will be tested, depending on feature availability:

1. Navigation
2. Signup / Registration
3. Login / Logout
4. Product Search
5. Product Details
6. Shopping Cart
7. Checkout and Address
8. Payment and Order Management

## 4. Testing Approach
- Perform manual functional testing.
- Prepare test scenarios and detailed test cases.
- Execute test cases using valid and invalid test data.
- Record actual results and Pass/Fail status.
- Document defects with steps to reproduce.

## 5. Types of Testing
- Functional Testing
- Positive Testing
- Negative Testing
- UI Testing
- Basic Validation Testing

## 6. Test Environment
- Application: ShoppersStack
- Testing Type: Manual Testing
- Browser: Google Chrome
- Test Data: Dummy data only

## 7. Entry Criteria
- The application is accessible.
- The feature to be tested is available.
- Test scenarios and test cases are prepared.

## 8. Exit Criteria
- Planned test cases have been executed where possible.
- Test results have been documented.
- Identified defects have been recorded.
- Testing limitations have been documented.

## 9. Test Deliverables
- Test Plan
- Test Scenarios
- Test Cases
- Test Execution Results
- Defect Reports

## 10. Limitations
- Testing depends on the features available in the application.
- Some features may be unavailable or restricted.
- Payment testing will only be performed if an authorised test or sandbox environment is available.

## 11. Project Status
Manual testing is in progress. Test scenarios, test cases, execution results, and defects will be updated as the project progresses.

## 12. Roles and Responsibilities
The tester is responsible for:
- Preparing test scenarios and test cases.
- Executing test cases.
- Recording actual results and test status.
- Reporting and documenting identified defects.

## 13. Test Data and Security
- Use dummy test data wherever possible.
- Do not publish real passwords or personal information.
- Use only authorised test payment methods.
- Do not perform unauthorised transactions.

## 14. Risks and Mitigation
**Risk:** Some application features may be unavailable.

**Mitigation:** Document unavailable features and continue testing accessible modules.

**Risk:** Payment functionality may not support test transactions.

**Mitigation:** Test payment flows only in an authorised test or sandbox environment.
